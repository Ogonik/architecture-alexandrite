# ADR Трассировка в сервисах Alexandrite

## Мотивация

Трейсинг даст компании возможность оперативно видеть, в каком из сервисов был нарушен бизнес-процесс работы с заказом. 

### 3-5 технических и бизнес-метрик решения
 - Время разбора инцидента (понижается)
   - Удовлетворенность пользователей при общении с тех поддержкой (повышается)
   - Время на составление багрепорта (снижается)
 - Единая визуализация характерных времен прохождения запросов
   - Время на анализ производительности тех или иных сервисов при определенных условиях (снижается)

## Предлагаемое решение

Внедряем трейсинг на OpenTelemetry + Jaeger. 
 - инструментирование систем SDK Opentelemetry
 - разворачивание opentelemetry collector для агрегации трейсов
 - разворачивание jaeger для сбора, персистентного хранения и визуализации трейсов
 - TTL 3-5 дней

Диаграмма С4 для решения
jewerly_c4_model_tracing.drawio


### Список данных для трейсинга
- trace_id -- присваивается на фронте при любом запросе к backend
- span_id
  - method_name
  - payload (при необходимости) 

## Компромиссы
### В каких случаях трейсинг не принесёт пользы 
 - отсутствие необходимости (нет use cases для применения)
 - слабо распределенная обработка данных в бизнес-процессах (1-2 этапа)

### В каких случаях трейсинг пока невозможен
 - отсутствие ресурсов на внедрение
 - отсутствие необходимости


### В каких случаях трейсинг и его реализация обойдётся слишком дорого.
- высокий RPS


## Аспекты безопасности

- ролевая модель в Jaeger
- AD аутентификация в JaegerUI
- отдельные ТУЗ для доступа на сервера

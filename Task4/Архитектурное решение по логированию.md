## Предлагаемое решение

### Для каких систем нужно настраивать логирование и трейсинг в первую очередь
 - 1й этап: Централизованный сбор логов со всех сервисов frontend и backend
 - 2й этап: Централизованный сбор логов с СУБД и других инфраструктурных сервисов 

### Уровни логирования:
 - Info - значимое изменение свойств бизнес-сущности, переход по этапам бизнес-процесса, инициация и окончание интеграционных процессов
 - Warning - любые преодолимые ошибки приложений
 - Debug - максимально подробные сообщения, которые должны позволить мысленно повторить вычисления приложения с т.з. бизнес-логики при известных входных данных

### Технологии
 - log4j - инструментирование Java приложения
 - log4net (Serilog) - инструментирование C# приложения
 - sentry - обработка ошибок фронтэнд части
 - Opensearch + OPensearchDashboards - хранение логов, TTL 7-30 дней
 - fluentd - сбор локальных логов и отправка в Opensearch

### Политика безопасности 
 - Ролевая модель на индексах в Opensearch
 - аутентификация AD + пользователи в специфические группы

### Политика хранения логов
 - TTL 7-30 дней
 - 1 индекс на 1 сервис на 1 сутки

### Нужно ли настроить какой-то алертинг?
Нужно ли искать аномалии? - нет. Для этого есть мониторинг

### Критерии для выбора технологии
 - Лицензия
 - Стоимость
 - Наличие опыта у команды
 - Total ownership cost (CPU, RAM, HDD)
 - Наличие готовых конфигураций в облаке компании
